# Audio & Ambience — Design

## Summary

The game has been completely silent since v1. This milestone gives it sound:
a soft ambient bed that crossfades between an outdoor and a dungeon mood as
the character travels, plus short one-shot cues for the moments already
worth noticing on screen — a hit landing, a heal, a level-up, and a quest
being accepted or turned in. All audio is procedurally synthesized (plain
Python `wave`/`math`, no external samples), the same "generate it ourselves
rather than risk a licensing/extraction problem" approach already used for
this project's pixel-art icons and terrain tiles.

## Goals

- A looping ambient bed that's always playing, with a distinct mood per
  broad zone type (calm outdoor pad for Thornfield Meadow/Blackthorn
  Forest, a lower and darker drone for Sundered Crypt), crossfading rather
  than cutting when the character crosses into a new one.
- Short SFX for damage dealt, healing, leveling up, accepting a quest, and
  turning one in — cues for events a spectator is already watching happen
  on screen and in the activity log.
- Zero new coupling into gameplay code beyond one new signal
  (`zone_changed`) — the audio system is a pure listener, exactly like
  every UI script in this project (`unit_frame.gd`, `quest_tracker.gd`,
  ...), never able to affect what the AI does.
- Every sound short/soft enough to not become grating over a long spectate
  session — the hit sound in particular plays very often (every auto-attack
  and every Rend/Heroic Strike hit), so it's a brief, soft filtered
  noise-click rather than a harsh sample.

## Non-Goals

- No positional/3D audio (no per-enemy panning or distance falloff) — a
  single flat 2D soundscape is enough for a top-down spectator view where
  the camera mostly follows the one character anyway.
- No music tracks with melody/structure — the "ambient" beds are static
  sustained chords with slow amplitude swell, not composed music.
- No per-ability distinct SFX (Rend/Heroic Strike/Charge/Second Wind all
  share the generic hit sound rather than each getting a unique cue) — a
  reasonable v1 scope line, extendable later without restructuring anything
  here.
- No audio settings/mute toggle in the UI — out of scope for this slice,
  same "one solid vertical slice per milestone" discipline as every prior
  pass.

## Architecture

### New files

```
/assets/audio
  sfx_hit.wav              ~90ms soft filtered noise click (auto-attack/
                            Rend/Heroic Strike impact)
  sfx_heal.wav              ~320ms two-note ascending chime (Second Wind /
                            health potion)
  sfx_levelup.wav           ~900ms four-note ascending fanfare
  sfx_quest_accept.wav      ~160ms single upward blip
  sfx_quest_complete.wav    ~450ms three-note triumphant resolve
  ambient_outdoor.wav       8s seamless loop, warm A-major pad, slow swell
  ambient_dungeon.wav       10s seamless loop, low G-minor-leaning drone
                            with a detuned beating layer for unease
/scripts/audio
  audio_director.gd         Node script, added once to Main.tscn; owns
                            every AudioStreamPlayer and all playback
                            decisions
```

All seven WAVs were generated by a one-off Python script (plain `wave` +
`struct` + `math`, no external libraries or samples) using simple additive
sine synthesis, ADSR envelopes, and light noise-filtering — not committed
as a build step, just how the assets were produced, the same way the
pixel-art icons were produced by one-off PIL scripts.

### Modified files

- `scripts/autoload/game_state.gd` — one new signal,
  `zone_changed(zone_id: String)`, emitted whenever the character enters a
  new zone. Same one-way emit-only/listen-only rule as every existing
  signal here.
- `scripts/entities/character.gd` — `_sync_current_zone()` now also emits
  `zone_changed(zone_id)` right after its existing `log_event("Arrives in
  ...")` call. Nothing else about zone-entry detection changes.
- `scenes/Main.tscn` — new `AudioDirector` `Node` (with `audio_director.gd`
  attached), a sibling of `DayNightCycle`/`World`/`Character`/`UI`.

### Why AudioDirector builds its AudioStreamPlayers in code instead of as scene child nodes

Every player is a plain leaf node with no need for scene-editor placement
(no position, no scene-specific tuning) — building all seven in `_ready()`
keeps the scene tree minimal and the whole audio setup in one file, the
same reasoning `decoration_scatter.gd` already uses for building its child
sprites in code rather than hand-placing them in a `.tscn`.

### Why looping is set on the loaded resource at runtime, not via import config

There's no editor GUI available in this environment to configure an
asset's `loop_mode` through the Import dock, and hand-authoring `.import`
files blind is fragile. `AudioStreamWAV.loop_mode` is a plain settable
property on the resource instance, so `_make_ambient_player()` sets
`AudioStreamWAV.LOOP_FORWARD` on the loaded stream directly before handing
it to the player — works regardless of whatever the asset's own import
settings default to, and is verified directly in testing (see below)
rather than assumed.

### Why a signal-driven crossfade instead of always having both players active

Two `AudioStreamPlayer`s loop *continuously* from `_ready()` onward (so
there's never a startup gap or restart-from-zero glitch on a zone change),
and `zone_changed` just tweens each one's `volume_db` toward -8 or -80 over
2 seconds — the "currently silent" bed still advances in lockstep,
so switching back to it later resumes in-phase rather than restarting.
Simpler and glitch-free compared to stopping/starting streams on transition.

### Quest accept vs. complete from one signal

`quest_changed(quest_name, progress, count)` already encodes both events
(see its own doc comment in `game_state.gd`): `quest_name == ""` is always
a turn-in, and a non-empty name different from the last one seen is always
a fresh accept. `AudioDirector` tracks `_last_quest_name` purely to tell
these apart — no gameplay code needed to change, and a same-quest
progress-only update (e.g. `("Bandit Trouble", 1, 2)` following
`("Bandit Trouble", 0, 2)`) correctly does *not* replay the accept chime.

## Error Handling / Edge Cases

- `_make_ambient_player()` only sets `loop_mode` when the loaded resource
  is actually an `AudioStreamWAV` (checked via `is`) — fails closed rather
  than erroring if a stream type ever changes.
- The crossfade tween is explicitly killed and replaced (`_ambient_tween`)
  on every `zone_changed`, so a rapid back-and-forth zone transition (e.g.
  a corridor edge case) can't leave two competing tweens fighting over the
  same `volume_db` property.
- SFX players are single, reused `AudioStreamPlayer`s rather than spawning
  one per event — a rapid flurry of hits (Rend tick + Heroic Strike +
  auto-attack landing close together) just retriggers the same player,
  Godot's default behavior for calling `.play()` on an already-playing
  stream (cuts to the new playback rather than erroring or stacking).

## Testing / Validation

Live headless runs (Godot 4.7 under Xvfb), same method as every prior
milestone:

- A direct signal-wiring test (`GameState.emit_signal(...)` for each of
  `damage_dealt` twice (heal/non-heal), `character_leveled_up`,
  `quest_changed` three times) confirmed every handler fires and the
  correct `AudioStreamPlayer` reports `playing == true` immediately after,
  the quest player's `.stream` correctly switches between the accept and
  complete cues, and a same-quest progress-only update does *not* replay
  the accept chime.
- Confirmed `AudioStreamWAV.loop_mode` reads back as `LOOP_FORWARD` (1) on
  the ambient stream after `_make_ambient_player()` runs.
- Confirmed the ambient crossfade: forcing `zone_changed("sundered_crypt")`
  correctly drove `outdoor_db` to -80 and `dungeon_db` to -8 within the
  2-second tween, and forcing `zone_changed("thornfield_meadow")`
  correctly crossfaded back.
- A full live playthrough (real AI play, not forced signals) across both
  outdoor zones and into Sundered Crypt, through multiple level-ups and
  quest accept/turn-in cycles (`Cull the Wolves` -> `Bandit Trouble` ->
  `Dire Wolf Hunt`), produced zero `SCRIPT ERROR` lines with
  `AudioDirector` active the whole time.

## How We'll Know This Is Done

The spectator experience now has sound: a mood-appropriate ambient bed
that shifts as the AI travels between the meadow, the forest, and the
dungeon, and short cues that land in sync with the moments already visible
in the activity log and on screen — without a single line of gameplay code
needing to know audio exists.
